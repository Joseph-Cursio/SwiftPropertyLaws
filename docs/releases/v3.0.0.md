# SwiftPropertyLaws v3.0.0

**Released:** 2026-06-27
**Tag:** `v3.0.0`
**Previous release:** [v2.6.0](https://github.com/Joseph-Cursio/SwiftPropertyLaws/releases/tag/v2.6.0)

## TL;DR

A major push on **generator derivation** in `PropertyLawCore`: the strategist now
covers the plain value-type world end-to-end — composite members, known value types,
**nested custom types**, **enums with payloads**, and **user-defined-init structs** —
plus **typealias resolution** and a new **scaffolding** path that emits best-effort
`gen()` stubs (with `<#…#>` placeholders) for types that can't be fully auto-derived.
Measured on a real 478-type app, derivable types went **19 → 64 (3.4×)** with **104
scaffolds** for the partial cases.

This is a major bump because the `PropertyLawCore` derivation surface changed in a few
source-breaking ways (see **Breaking changes**).

## What's new

### Generator derivation tiers

The discovery plugin / `@PropertyLawSuite` now derive generators for far more shapes:

- **Composite members** — `T?`, `[T]`, `Set<T>`, `[K: V]` (sugar and generic spellings,
  nested) compose `swift-property-based` combinators.
- **Known value types** — `Character`, `Date` (with `Foundation` import propagated to the
  generated file).
- **Nested custom types** — a whole-module `GeneratorResolver` inlines a sibling type's
  generator (or references `Type.gen()`), with cycle detection and memoization.
- **User-init structs** — derive by lifting through a user-defined initializer when the
  synthesized memberwise init is suppressed.
- **Enum payloads** — enums with associated values derive via `Gen.oneOf(...)` over
  per-case generators.
- **Typealiases** — known stdlib/Foundation aliases (`TimeInterval` → `Double`, …) and
  user-declared aliases collected from source resolve to their underlying type.

### Generator scaffolding (`--scaffold-out`)

For a type that can't be *fully* derived, the discovery tool can now write a best-effort
`gen()` stub to a separate, opt-in file — derivable slots filled, the rest left as
`<#Generator<T>#>` editor placeholders for the developer to complete. PropertyLawCore
emits **holes**, never guesses: closures and opaque/external types stay placeholders.

### `GeneratorPlan`

Generator composition is now a structured `GeneratorPlan` tree (leaf / optional / array /
set / dictionary / `.hole`) behind the string emitters — the foundation for scaffolding
and for downstream refinement.

## Breaking changes

- **`MemberSpec.rawType` is now `RawType?`** (was `RawType`). The canonical field for
  emission is the new **`MemberSpec.generatorExpression`** — migrate
  `member.rawType.generatorExpression` → `member.generatorExpression`.
- **`DerivationStrategy` gained cases** `.initializerBased(arguments:)` and
  `.enumCases(cases:)`. Exhaustive `switch`es over `DerivationStrategy` must handle them.
- **`DerivationStrategist.strategy(for:)` gained a defaulted `resolve:` parameter**
  (`CustomTypeResolver`). Existing `strategy(for: shape)` calls compile unchanged.
- **`ComposedGenerator` is now public and plan-backed** (`expression` / `requiredImports`
  are derived from its `plan`); the new public `GeneratorResolver` supplies the resolve
  closure for nested-type derivation.

## Downstream

SwiftInferProperties consumes `PropertyLawCore`; bump its pin to `from: "3.0.0"` and apply
the two-switch + `generatorExpression` migration above.
