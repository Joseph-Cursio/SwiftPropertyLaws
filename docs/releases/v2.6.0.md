# SwiftPropertyLaws v2.6.0

**Released:** 2026-06-26
**Tag:** `v2.6.0`
**Previous release:** [v2.5.0](https://github.com/Joseph-Cursio/SwiftPropertyLaws/releases/tag/v2.5.0)

## TL;DR

Three threads land together: the kit's first **two-operation algebraic protocol**
(`Ring`, 11 Strict laws), an **internals refactor** (shared per-arity law builders,
centralized suite verify/throw policy, deduped inherited-law collection), and
**backend shrinking** — per-trial laws now report the *minimal* failing input, not the
first one. Shrinking is additive and opt-in per law; Equatable is wired as the proving
family.

## What's new

### `Ring` — kit-defined two-operation protocol

```swift
public protocol Ring {
    static var zero: Self { get }
    static var one: Self { get }
    static func add(_ a: Self, _ b: Self) -> Self
    static func multiply(_ a: Self, _ b: Self) -> Self
    static func negate(_ a: Self) -> Self
}
```

`Equatable` is required to *check* the laws (the generator's value type), not to
*declare* the conformance — same posture as every kit-defined protocol.

The kit's first structure where two operations interact through distributivity.
Eleven Strict-tier laws: the additive abelian group (`addAssociativity`,
`addCommutativity`, `add{Left,Right}Identity`, `add{Left,Right}Inverse`), the
multiplicative monoid (`multiplyAssociativity`, `multiply{Left,Right}Identity`), and
`{left,right}Distributivity`. Standalone (no protocol-DAG inheritance — a ring's
additive and multiplicative structures don't refine the kit's single-op chain).
Verified by `checkRingPropertyLaws(..., laws: LawSelection = .all)`. Closes the last
algebraic structure SwiftInferProperties already infers (see the v1.10 plan).

### Backend shrinking — minimal counterexamples (v2.6.A)

Per-trial laws now shrink a failing input to a minimal still-failing one before
reporting. `CheckResult` gains two additive fields:

```swift
public let shrunkFrom: String?   // pre-shrink counterexample; nil when shrinkSteps == 0
public let shrinkSteps: Int      // 0 when no shrinker / already minimal
```

`outcome`'s `counterexample` holds the **minimal** form; `shrunkFrom` holds the
original. Design notes: [`docs/v2.6 Backend Shrinking plan.md`](../v2.6%20Backend%20Shrinking%20plan.md).

- **Driver-level, not backend-level.** Shrinking is a `PerLawDriver` policy that
  re-runs the law's own `property` as the failure oracle. `PropertyBackend`,
  `BackendCheckResult`, and `SwiftPropertyBasedBackend` are **untouched** — zero
  public-API change, so downstream custom-backend conformers keep compiling.
- **Closure seam preserved.** The shrinker is a value-level
  `(@Sendable (Input) -> [Input])` closure (built from swift-property-based's
  `FixedWidthInteger.shrink(towards:)`); the kit never threads a `Generator`.
- **Opt-in per law.** `runUnaryLaw` / `runBinaryLaw` / `runTernaryLaw` and
  `checkEquatablePropertyLaws` gain a defaulted `shrink:`. Laws that omit it behave
  exactly as before (`shrinkSteps == 0`). The remaining 21 families are a mechanical
  per-family rollout.
- **Correctness.** Float tolerance holds by construction (the oracle is the law's own
  comparison); shrinking is deterministic given the seed; throw fidelity preserved.

### Internals refactor

- Per-arity builders extracted (`runUnaryLaw` / `runBinaryLaw` / `runTernaryLaw`) — call
  sites declare only law identity, property, and counterexample text.
- Suite verify/throw policy centralized; test-stub emitter shared.
- Inherited-law collection, `KnownProtocol` switches, and member inspection deduped.

## Compatibility

Source-compatible. `CheckResult` gains `shrunkFrom` / `shrinkSteps` (additive, with
defaults); `Outcome` is unchanged. New `shrink:` parameters are defaulted, so existing
callers — including SwiftInferProperties-generated stubs — are unaffected.

## Tests

491 tests, all passing (`BackendShrinkingTests` adds 5; the Ring suite adds its own).
SwiftLint clean — the sole `large_tuple` site (the ternary tuple shrinker, intrinsic to
3-value laws) is waived with a scoped inline `disable`/`enable`, not a config change.
